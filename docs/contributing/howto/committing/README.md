# Committing

## Commit style

Conventional commits: `<type>(<scope>): <subject>`.

Valid types: `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`,
`build`, `ci`, `chore`, `revert`.

Rules (enforced by the `check-commit-message` hook):

- Subject: ≤72 chars recommended, ≤120 max.
- No AI attribution (no `Co-Authored-By` with AI names, no "generated by …").
- No ticket references in the body — put those in the PR description.

## Hooks

Hooks are generated from `flake.nix` via
[git-hooks.nix](https://github.com/cachix/git-hooks.nix) and installed by
`nix develop`. `.pre-commit-config.yaml` is generated — do not edit or commit
it (it is gitignored).

Run them manually:

```bash
nix flake check                          # all hooks, sandboxed
nix develop -c pre-commit run --all-files  # all hooks, outside the sandbox
```

The `check-commit-message` hook runs on the `commit-msg` stage, so it is
skipped by `nix flake check` / `pre-commit run --all-files`.
